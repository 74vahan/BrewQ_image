# 03. Архитектурные решения

Статус: **Фаза 1: утверждено** (09.10.2026). Формат: что выбрано →
альтернативы → почему. Продуктовые решения — в
`BrewQ_infra/memory/06-decisions.md`.

1. **Разбивка (решение пользователя).** Здесь Docker + Terraform + nginx на
   хосте; backend, панель и CI/CD с деплоем — в `BrewQ_infra`.

2. **GCP, `apply` позже (решение пользователя).** Аккаунта нет; Terraform
   пишется полностью, проверяется `fmt`/`validate`/`check-templates.sh`.

3. **nginx на хосте, не в контейнере** (как MiasinInfra). Конфиг — артефакт
   сервера и домена, сертификат и reload решаются на хосте, деплою не нужен
   sudo, панель отдаётся с диска.

4. **Панель — статика, контейнера `web` и порта 8082 нет.** Черновик
   Фазы 0 предлагал web-контейнер; отказ — ради атомарного симлинка релизов и
   отката без пайплайна (как в Miasin).

5. **Compose: только `db` (`mysql:8.4`) и `api`.** 8.4 — LTS-ветка MySQL 8,
   совпадает с выбором пользователя «MySQL 8».

6. **`docker/` попадает на сервер деплоем `BrewQ_infra`, а не Terraform'ом.**
   - Альтернатива: `null_resource` кладёт `docker/` на VM (как конфиг nginx).
   - Почему нет: правка Dockerfile требовала бы `apply` с ноутбука, а CI
     `BrewQ_infra` не мог бы собрать реальный образ. Сейчас CI клонирует этот
     (публичный) репозиторий на `BREWQ_IMAGE_REF` и собирает тот же образ,
     что поедет на сервер. Цена — CI `BrewQ_infra` зависит от этого
     репозитория; закреплённый ref делает это управляемым. Если репозиторий
     станет приватным — секрет `BREWQ_IMAGE_TOKEN` (PAT `contents:read`).

7. **`.env` пишет только bootstrap, один раз** (как Miasin). Иначе том MySQL
   и backend разошлись бы по паролю, а `BARISTA_TOKEN_SECRET` менялся бы на
   каждом деплое и разлогинивал панель. Деплой без `.env` падает.

8. **Порт backend `127.0.0.1:8081`, контейнер слушает 8000.** Контракт —
   одна переменная `backend_port` / `BACKEND_PORT` с одинаковыми умолчаниями
   в Terraform и compose.

9. **MySQL не публикуется; firewall deny 3306** документирует намерение.
   Dev-оверлей — `127.0.0.1:53306`.

10. **Rate limit на nginx, JSON-тело 429.** Перебор пароля баристы
    (5/мин на `/api/barista/login`) и массовое создание клиентов случайными
    `X-Device-Id` (10 r/s на `/api/`) режутся до backend; таблиц для этого
    не нужно.

11. **`ssh_user` = `brewq`**, совпадает с умолчанием `SERVER_USER` в CI
    `BrewQ_infra`.

12. **App Links не переносятся из Miasin** — в BrewQ нет веб-ссылок,
    открывающих приложение.

13. **Код, конфиги, скрипты и workflow — на английском** (10.10.2026).
    Правило №5: кириллица в коде только в локализации. Русские
    `description`/`error_message`, сообщения скриптов, имена шагов workflow и
    комментарии переведены на английский; поведение не менялось (те же
    переменные, условия валидации, коды выхода, плейсхолдеры шаблонов).
    Исключение — русская строка стаб-страницы баристы (en/ru/hy) в
    `terraform/scripts/bootstrap.sh.tftpl:126`: это локализованный
    пользовательский текст; `check-cyrillic.sh` на ней даёт единственный
    ERROR. Allow-list скрипта не менялся. Документация (`*.md`) остаётся
    русской.

## Принятые риски

- **Без домена — HTTP.** Пароль баристы и токен идут открытым текстом, пока
  не задан `domain` и не выпущен сертификат. Для боевого запуска домен
  обязателен (вопрос пользователю).
- **Бэкапов БД нет.** Том на диске VM — единственная копия. Кандидат на
  отдельную задачу: ежедневный `mysqldump` в приватный GCS-бакет.
- **Один сервер, без мониторинга.** Достаточно для одной кофейни на старте.
